1. Giới thiệu

BMad là một «tòa soạn ảo» gồm các chuyên gia. Cho người làm phân tích & nghiên cứu thị trường, bạn chỉ cần biết hai kiểu agent:

👤 Persona AgentChuyên gia cá nhân

Một «người» bạn trò chuyện trực tiếp như đồng nghiệp. Phù hợp cho: hỏi xin tư vấn, brainstorm, lấy ý kiến chuyên môn nhanh. Ví dụ: nói chuyện với Mary (BA), Carson (Brainstorming), Dr. Quinn (Problem Solver).

Dùng bất kỳ lúc nào
📋 Workflow SprintQuy trình từng bước

Một quy trình dài hơi nhiều bước, ra deliverable hoàn chỉnh (báo cáo nghiên cứu, market sizing, ICP profile). Phù hợp cho: vào ngành mới, validate hypothesis, deep-dive đối thủ. Ví dụ: Market Research, Customer Research Sprint.

Theo phase
Quy tắc vàng cho analyst: Bắt đầu mọi project nghiên cứu bằng Mary (BA) để chốt phạm vi câu hỏi — rồi mới gọi sprint sâu (MR / DR / CRS / TR). Đừng nhảy thẳng vào sprint khi chưa biết mình muốn trả lời câu gì → tốn 1–2 tiếng vô ích.
💬 Cách gọi agent — 3 kiểu đều hiểu:
  1. Theo skill name (kỹ thuật): «chạy bmad-market-research» — chính xác 100%.
  2. Theo display name (chính thức): «tôi muốn nói chuyện với Business Analyst».
  3. Theo tên persona (thân mật): «Mary ơi, audit giúp tôi thị trường F&B», «hỏi Dr. Quinn về root cause».

→ Bạn còn có thể gọi nhanh bằng menu code (xem bảng tra cứu): «chạy MR», «gọi BA».

2. Setup & cách gọi agent trong OpenCode

Phần này dành cho người chưa quen — đọc 2 phút là dùng được. Nếu đã quen, bỏ qua sang Mục 3.

2.1 Kiểm tra BMad đã cài chưa

Mở OpenCode trong thư mục dự án của bạn, gõ trong chat:

bạn có thấy skill bmad-agent-analyst không?

Nếu agent trả lời có và liệt kê Mary — Business Analyst → đã cài. Nếu trả lời không tìm thấy, bạn cần cài BMad trước (nhờ một developer hoặc chạy script cài đặt trong README dự án).

2.2 Ba cách gọi agent — chọn cách nào cũng được

OpenCode hiểu cả tiếng Việt tự nhiên lẫn slash command. Dưới đây là ba lối gọi phổ biến nhất:

Cách 1 — Tên personatự nhiên nhất

Cứ nói chuyện như với đồng nghiệp:
Mary ơi, giúp tôi audit thị trường F&B tại Sài Gòn

Cách 2 — Display namechính thức hơn

Dùng khi quên tên persona:
tôi muốn nói chuyện với Business Analyst

Cách 3 — Skill namechính xác 100%

Khi agent không hiểu ý bạn:
chạy bmad-market-research

Mẹo OpenCode: OpenCode hỗ trợ gọi skill qua dấu / (gõ / rồi tab để xem danh sách). Ví dụ /bmad-market-research. Nhưng gõ tiếng Việt tự nhiên cũng được — agent sẽ tự nhận diện và gọi đúng skill.
⚠️ Lưu ý quan trọng: Sprint dài (Market Research, Customer Research, Domain Research) có thể chạy 30–90 phút và hỏi bạn nhiều câu trong quá trình. Đừng đóng cửa sổ giữa chừng — trả lời từng câu cho đến khi agent xuất file kết quả vào thư mục _bmad-output/.

3. Cấu trúc làm việc với AI

Trước khi gọi agent đầu tiên, đọc mục này 5 phút. Nó sẽ tiết kiệm cho bạn hàng tuần loay hoay tìm lại file và lặp lại câu hỏi với AI.

3.1 Mục tiêu — bạn đang làm gì khi research với AI?

Mọi project research với AI nên hướng tới ít nhất một trong ba mục tiêu sau. Xác định rõ ngay từ đầu để chọn agent đúng và biết khi nào dừng.

🎯 Mục tiêu 1Trả lời 1 câu hỏi cụ thể

Decision support. Bạn cần quyết định ngay: có vào thị trường này không, chọn vendor nào, ICP nào ưu tiên. Output: 1 trang khuyến nghị + dẫn chứng. Thời gian: 1–3 giờ.

📄 Mục tiêu 2Tạo deliverable chia sẻ stakeholder

Báo cáo hoàn chỉnh. Khách hàng, sếp, đồng đội cần đọc. Output: file markdown có cấu trúc, hoặc HTML/PPT. Thời gian: 1–2 ngày, có review/edit.

📚 Mục tiêu 3Build knowledge base dài hạn

Tích lũy kiến thức. Project nhiều tháng, cần lưu insight để tham chiếu. Output: folder research có index, có naming convention. Thời gian: liên tục.

3.2 Cấu trúc thư mục đề xuất

BMad đã có sẵn convention. Tạo folder này trước khi gọi sprint đầu tiên — agent sẽ tự xuất file vào đúng chỗ.

your-project/
├── README.md                       ← Mục tiêu, stakeholder, deadline project
├── _bmad-output/
│   └── planning-artifacts/
│       └── research/                ← Output của MR / DR / CRS / TR
│           ├── domain-{topic}-{date}.md
│           ├── market-{topic}-{date}.md
│           ├── customer-{topic}-{date}.md
│           └── tech-{topic}-{date}.md
├── docs/
│   ├── references/                  ← PDF, screenshot, link gốc
│   ├── interviews/                  ← Note phỏng vấn khách hàng
│   └── decisions/                   ← ADR — quyết định lớn + lý do
└── _bmad-output/brainstorming/      ← Output các phiên brainstorm
Cách tạo nhanh: Mở OpenCode trong thư mục project, gõ:
tạo cấu trúc folder research chuẩn BMad cho project này
Agent sẽ tự tạo các folder con và file README.md mẫu.

3.3 Naming convention — đặt tên file thế nào

Pattern: {type}-{topic-slug}-{YYYY-MM-DD}.md — kebab-case, không dấu tiếng Việt, ngày ở cuối để sort theo thời gian.

3.4 Bốn quy tắc làm việc với AI hiệu quả

Đây là điểm khác biệt giữa người «chat với AI cho vui» và người ra được kết quả thực sự.

① Mở project bằng READMEcontext-first

Viết 1 file README.md ngắn (10–20 dòng) gồm: mục tiêu project, stakeholder, deadline, các câu hỏi cần trả lời. Mỗi lần mở chat mới, paste README vào — agent có context ngay, không hỏi lại từ đầu.

② Câu hỏi cụ thể, không mơ hồscoping

Tránh: «phân tích thị trường F&B».
Nên: «thị trường cafe high-class tại Sài Gòn quận 1–3, ngân sách marketing 10k USD/tháng, B2C lẫn B2B, có cơ hội gì cho thương hiệu mới ra đời 2025?». Càng cụ thể, output càng dùng được.

③ Lưu output ngay vào filepersistence

Mọi sprint đều tự xuất file vào _bmad-output/. Với các câu hỏi nhanh trong chat, copy câu trả lời ra file — đừng để trôi trong history. Sau 1 tuần bạn sẽ quên đã hỏi gì.

④ Adversarial Review trước khi gửisafety net

Bất kỳ kết luận quan trọng nào — chạy bmad-review-adversarial-general (AR) để rà soát giả định ngầm, lỗ hổng logic. AR sẽ «đóng vai stakeholder hoài nghi» trước khi stakeholder thật làm điều đó với bạn.

4. Khi nào dùng cái nào?

Ba tình huống thường gặp nhất của một researcher — chọn cái gần nhất với việc bạn đang làm.

🎯 Tình huống A — Tôi vào một ngành/thị trường mới hoàn toàn

1. Mary (BA): chốt câu hỏi nghiên cứu → 2. DR: hiểu đặc thù ngành → 3. MR: đo thị trường, đối thủ → 4. CRS: ICP & khách hàng → 5. Mary (BA): tổng kết & kết luận

Ví dụ: «Tôi muốn vào ngành AI forecasting cho nhà máy nhựa, chưa biết gì.» → DR → MR → CRS theo thứ tự.

💡 Tình huống B — Tôi có ý tưởng/sản phẩm cụ thể, cần validate

1. Mary (BA): phân tích vấn đề → 2. CRS: nghiên cứu khách hàng mục tiêu → 3. Victor: thử Blue Ocean / JTBD → 4. AR: rà tìm lỗ hổng

Ví dụ: «VLU Family Academy có thật sự là wedge tốt?» → CRS để hiểu ICP, Victor cho innovation angle, AR để không tự lừa mình.

📝 Tình huống C — Tôi chỉ cần 1 câu trả lời nhanh, không cần sprint

Mary (BA) trong chat → Nếu bí ý: gọi Carson → Cần root cause: gọi Dr. Quinn

Ví dụ: «So sánh nhanh Databricks vs Snowflake cho Phase 1 VinaCapital», «Tại sao tỷ lệ post-grad enrollment tại Việt Nam thấp?».

5. Năm agent cốt lõi cho researcher

Chỉ cần nhớ 5 cái này là đủ 90% công việc phân tích & nghiên cứu thị trường. Mary là persona — gọi bất kỳ lúc nào; MR/DR/CRS/TR là sprint — chạy khi cần deliverable hoàn chỉnh.

1-Analysis Phân tích nền tảng Anytime Gọi bất kỳ lúc nào
Mary — Business Analystbmad-agent-analyst
BA

Đồng nghiệp số 1. Phân tích viên cấp cao biết Porter's Five Forces, SWOT, root-cause, competitive intelligence. Gọi Mary khi cần nghĩ to, gỡ requirement mơ hồ, hoặc xin tư vấn nhanh về vấn đề chiến lược. Không ra deliverable cố định — đối thoại linh hoạt.

Anytime
Market Researchbmad-market-research
MR

Quy trình nghiên cứu thị trường & cạnh tranh. Ra báo cáo có cấu trúc: quy mô thị trường (TAM/SAM/SOM), trend, đối thủ, segment, cơ hội. Dùng khi bắt đầu ngành mới hoặc đánh giá entry strategy. Tốn thời gian hơn nhưng output dùng được làm tài liệu.

1-Analysis
Domain Researchbmad-domain-research
DR

Nghiên cứu domain/ngành. Khác MR ở chỗ đi sâu vào đặc thù ngành: thuật ngữ, mô hình kinh doanh điển hình, players chính, công nghệ phổ biến, quy định pháp lý. Dùng trước MR nếu ngành mới lạ. Bạn đã dùng cho AI Forecasting nhà máy nhựa, CRM hospitality, VLU post-grad.

1-Analysis
Customer Research Sprintbmad-customer-research-sprint
CRS

Nghiên cứu khách hàng vi mô. ICP, Voice of Customer (VOC), Jobs-To-Be-Done (JTBD), mining review & community, profile đối thủ. Dùng song song với MR: MR nhìn thị trường, CRS hiểu khách hàng.

1-Analysis
Technical Researchbmad-technical-research
TR

Nghiên cứu công nghệ & kiến trúc. Khi research liên quan đến tech (AI/ML, fintech, SaaS stack, blockchain…), gọi TR để hiểu lựa chọn kỹ thuật, vendor, architecture. Bạn không cần biết code — TR giải thích như cho non-dev.

1-Analysis
Câu thần chú mở đầu: «Mary ơi, tôi đang nghiên cứu [chủ đề]. Mục tiêu của tôi là [kết luận muốn ra]. Bạn nghĩ tôi nên chạy MR, DR, hay CRS trước? Và câu hỏi nghiên cứu nên thu hẹp lại như thế nào?» → Mary sẽ giúp chốt scope trước khi chạy sprint. Đây là bước tránh lãng phí thời gian lớn nhất.

6. Trợ thủ sáng tạo (CIS)

Các agent CIS (Creative & Innovation Strategy) — gọi khi cần «xả ý tưởng», phá khung tư duy, hoặc đổi góc nhìn. Không bắt buộc nhưng cực kỳ hữu ích cho researcher.

Carson — Brainstorming Coachbmad-cis-agent-brainstorming-coach

Facilitator năng lượng cao, áp dụng «YES AND». Gọi khi bí ý tưởng, cần phá khối tư duy. Phù hợp giai đoạn đầu — chưa biết nên hỏi gì.

CIS
Dr. Quinn — Problem Solverbmad-cis-agent-creative-problem-solver

Sherlock của BMad. Dùng TRIZ, Theory of Constraints, Systems Thinking để truy gốc rễ vấn đề. Gọi khi câu hỏi là «tại sao X mãi không cải thiện?».

CIS
Victor — Innovation Strategistbmad-cis-agent-innovation-strategist

Cựu McKinsey. JTBD, Blue Ocean Strategy, business model innovation. Hỏi «đơn giản mà chí mạng». Gọi khi cần phá thị trường, không chỉ tham gia.

CIS
Maya — Design Thinking Coachbmad-cis-agent-design-thinking-coach

Empathy mapping, prototyping, user insight thực địa. Gọi khi nghiên cứu cần dữ liệu từ tương tác thật với người dùng (interview, observation).

CIS
Sophia — Master Storytellerbmad-cis-agent-storyteller

Bậc thầy 50+ năm storytelling. Gọi khi cần kể lại phát hiện nghiên cứu cho stakeholder — biến số liệu trừu tượng thành câu chuyện sống.

CIS
Brainstorming Workflowbmad-brainstorming
BSP

Phiên brainstorming có cấu trúc, nhiều kỹ thuật (SCAMPER, 6 thinking hats, mind-map…). Ra deliverable rõ ràng hơn chat tự do với Carson.

7. Đánh bóng output (rà soát · nén · chia file)

Researcher hay phải xử lý tài liệu dài. Đây là các skill core cực kỳ tiện — chạy sau khi đã có draft báo cáo.

Adversarial Reviewbmad-review-adversarial-general
AR

Review hoài nghi. Đọc lại tài liệu, tìm lỗi logic, điểm yếu, giả định ngầm. Bắt buộc chạy trước khi gửi kết luận cho stakeholder.

CoreBắt buộc
Edge Case Hunterbmad-review-edge-case-hunter
ECH

Đi qua mọi nhánh điều kiện, báo trường hợp chưa xử lý. Bổ trợ AR. Dùng cho phân tích kịch bản, financial model, scenario planning.

Core
Editorial Review — Prosebmad-editorial-review-prose
EP

Biên tập viên lâm sàng: rà từng câu, đề xuất sửa cụ thể dạng bảng 3 cột. Chạy sau khi viết xong báo cáo.

Core
Editorial Review — Structurebmad-editorial-review-structure
ES

Soát cấu trúc tổng thể: cắt phần thừa, sắp xếp lại, đơn giản hóa. Dùng khi báo cáo được ghép từ nhiều nguồn.

Core
Distillatorbmad-distillator
DG

Nén tài liệu dài thành bản «distillate» tối ưu cho LLM, không mất thông tin. Hữu ích khi muốn chuyển báo cáo cho agent khác đọc, hoặc tóm tắt cho stakeholder.

Core
Shard Documentbmad-shard-doc
SD

Tách tài liệu >500 dòng thành nhiều file nhỏ theo heading. Dễ quản lý, dễ review từng phần.

Core
Index Docsbmad-index-docs
ID

Tự sinh/cập nhật index.md tham chiếu mọi file trong thư mục. Dùng cho thư mục research nhiều file.

Core
Party Modebmad-party-mode
PM

Mở «phòng họp» nhiều agent cùng lúc — mỗi agent cho góc nhìn riêng về cùng 1 vấn đề. Hữu ích khi cần ý kiến đa chiều trước khi quyết định lớn.

Core
Advanced Elicitationbmad-advanced-elicitation

Đẩy LLM cân nhắc lại output gần nhất qua Socratic, first-principles, pre-mortem, red team. Gọi sau khi agent vừa đưa kết luận và bạn muốn nó nghĩ kỹ hơn.
